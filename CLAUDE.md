# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A personal portfolio site (fatihky.github.io) built from the TanStack Start "termfolio" template — a single-page "phosphor terminal" themed homepage (boot sequence, CRT overlay, mini terminal with fake commands, about/projects/log/skills/contact sections). Deployed as a static export to GitHub Pages.

## Commands

Package manager is **pnpm**.

```bash
pnpm install        # install deps
pnpm dev             # vite dev server on port 3000
pnpm build           # vite build -> dist/client (static, prerendered)
pnpm preview         # preview the production build
pnpm generate-routes # regenerate src/routeTree.gen.ts via `tsr generate` (usually automatic)
pnpm lint            # biome lint
pnpm format          # biome format
pnpm check           # biome check (lint + format), fixes organize-imports too
```

There is no test suite/runner configured in this repo.

CI (`.github/workflows/deploy.yaml`) runs `pnpm install --frozen-lockfile` then `pnpm run build` and publishes `dist/client` to GitHub Pages on every push to `master`.

## Architecture

- **TanStack Start + file-based router**: routes live in `src/routes/`. `src/routes/__root.tsx` defines the HTML shell (`<html data-theme={ACTIVE_THEME}>`, `HeadContent`, `Scripts`, TanStack devtools). `src/routes/index.tsx` just renders `HomePage`. `src/routeTree.gen.ts` is generated — never hand-edit it (it's excluded from Biome).
- **Everything lives on one page**: `src/components/pages/home.tsx` owns all page state (boot sequence progression, typewriter tagline, mini-terminal command history/input) and composes the section components from `src/components/home/`. Section components (`AboutSection`, `ProjectsSection`, `LogSection`, `SkillsSection`, `ContactSection`, `Hero`, `Nav`, `Footer`, `BootScreen`, `MiniTerminal`) are presentational and take their content as props.
- **Content is centralized in `src/components/home/data.ts`**: the `DATA` object (name, tagline, about, projects, experience, skills, links) is the single place to edit site content. `BOOT_LINES` drives the boot animation text/timing. `buildTerminalCommands(scrollTo)` defines the fake terminal's command table (`help`, `about`, `whoami`, `sudo`, etc.) — add new terminal commands here.
- **Theming**: `src/theme.ts` exports `ACTIVE_THEME`, a single string switch (`'phosphor' | 'daylight' | 'imperial' | 'turquoise' | 'rosewood'`) consumed by `__root.tsx` as `data-theme` on `<html>`. Palettes are defined in `src/styles.css`: the default `phosphor` palette sits in the `@theme { ... }` block as Tailwind v4 CSS variables (`--color-bg`, `--color-fg`, etc. — each also becomes a Tailwind utility like `bg-bg`, `text-fg-bright`), and every other theme is a `[data-theme='name'] { ... }` override block further down the same file. To add a theme: add the name to `ThemeName` in `theme.ts`, add a matching `[data-theme='...']` block in `styles.css` overriding the same variable set. `PhosphorStyles.tsx` injects the CRT/scanline/terminal CSS (not Tailwind-driven) that all themes share.
- **i18n via Paraglide**: `project.inlang/settings.json` configures locales (`en` base, `tr`) and message source (`messages/{locale}.json`). `src/paraglide/` is fully generated output (regenerated by `vite dev`/`vite build` via the `paraglideVitePlugin` in `vite.config.ts`) — don't hand-edit it. Runtime helpers (`getLocale`, `setLocale`, `locales`) and typed messages (`m.*`) are imported from `#/paraglide/runtime` and `#/paraglide/messages`. `src/components/LocaleSwitcher.tsx` demonstrates the pattern but is not currently wired into the page. `__root.tsx`'s `beforeLoad` sets `document.documentElement.lang` from `getLocale()`.
- **Path alias**: `#/*` (and `@/*`) resolve to `./src/*` (configured in both `package.json#imports` and `tsconfig.json`) — used for all intra-`src` imports instead of relative paths.
- **Styling**: Tailwind CSS v4 via `@tailwindcss/vite`, imported once in `src/styles.css` (`@import "tailwindcss"`). No `tailwind.config.js` — theme tokens are defined inline via the `@theme` at-rule in CSS.

## Conventions

- Biome (not ESLint/Prettier) handles lint + format: single quotes, 2-space indent, organize-imports on save/check. Run `pnpm check` before considering a change done.
- `src/routeTree.gen.ts` and `src/styles.css` are excluded from Biome's `files.includes` — don't expect lint/format to touch them.
- `src/paraglide/**` is generated — treat as build output, not source to edit.
